# PRD: AI 케이스 스터디 작성기 (Jae 블로그)

<sub>버전 v1.4 (이전 버전은 커밋 기록), 2026년 11월 24일 J 작성, 배포 https://blog---261117.web.app, 기준 화면 [프로토타입](../prototype.html), AI 작성기 [Claude 아티팩트](https://claude.ai/artifact/P6pJ9oB2nfDGJKTfgviAzA)</sub>

## 1. 개요
방문객이 거의 없고 작업 과정이 보이지 않아 의뢰가 들어오지 않는 1인 디자이너 블로그에서, 운영자가 메모만 넣으면 AI가 케이스 스터디와 인스타그램 문구를 만들어 소상공인과 스타트업 마케터를 데려오고, 한 줄 의뢰로 바로 의뢰하게 한다.

## 2. 문제
**데스크리서치**: 디자인과 구현을 모두 하는 것이 강점, 빈 작업 섹션과 적은 방문자가 약점(SWOT). 고객은 문제 해결 과정을 보고 고르고, 외주 플랫폼은 포트폴리오로 신뢰를 준다(3C).

| 문제 발굴: 사용자(방문자) | 문제 발굴: 관리자(운영자) |
|---|---|
| U1. 작업물과 과정을 볼 수 없어 믿고 맡기기 어렵다 | A1. 블로그에 방문객이 거의 없다 |
| U2. 무엇을 의뢰할지 몰라 의뢰서 쓰기가 막막하다 | A2. 작업을 케이스 스터디로 정리할 시간이 없다 |
| | A3. 작업을 알릴 홍보 문구를 쓸 여유가 없다 |

**문제 검증**: 의뢰자가 작업 과정을 보고 믿는지, 1인 프리랜서가 정리와 홍보 시간이 부족한지 공공 통계, 학술 논문, 공식 리포트 원문으로 확인한다. 결과: 검증 후 기입

**최종 정의**: 방문객이 거의 없고 찾아온 방문자도 과정을 볼 수 없어 의뢰하지 않으며, 운영자는 작업을 정리하고 알릴 시간이 없다.

## 3. 해결 방안
| 사용자 문제 | 해결 방안 |
|---|---|
| U1. 작업물과 과정을 볼 수 없다 | 요청, 과정, 결과를 보여 주고 의뢰 버튼을 둔다 (F3) |
| U2. 의뢰서 쓰기가 막막하다 | 한 줄로 비슷한 작업과 미리 채운 의뢰서를 준다 (F1, F2) |

| 관리자 문제 | 해결 방안 |
|---|---|
| A1. 방문객이 거의 없다 | 게시마다 인스타그램 문구로 데려온다 (F7) |
| A2. 정리할 시간이 없다 | AI 초안을 확인 후 게시한다 (F4, F5, F6) |
| A3. 홍보 문구를 쓸 여유가 없다 | 문구 3안 중 골라 복사한다 (F7) |

- **솔루션 정의**: 운영자는 메모만 남기고, 방문자는 과정을 보고 한 줄로 의뢰한다.

| 3.2 구분 | AS-IS | TO-BE |
|---|---|---|
| 컨셉 | 작업이 정리되지 않음 | AI가 정리, 사람이 확인 후 게시 |
| 타겟 | 적고 근거 없는 방문자, 바쁜 운영자 | 인스타그램으로 온 방문자, 시간을 아낀 운영자 |
| 비즈니스 모델과 가격 | 의뢰 수주 | 같음, 건당 AI 비용 0원 |
| 기능 | 빈 작업 카드, 긴 의뢰 폼 | 작성기, 작업 상세, 한 줄 의뢰, 문구 |
| 디자인 | 이미지와 이름 카드 | 과정을 읽는 상세 (7장) |

- **예상 성과 (OKR)**: 운영자가 작업 3건을 한나절 안에 케이스 스터디로 올리고, 방문자는 과정을 보고 의뢰를 시작한다. KR1 케이스 스터디 3건 게시, 건당 15~20분(메모 5분, AI 초안 1분, 검토·수정 10분, 게시·문구 3분, 11/25). KR2 초안의 없는 사실 0건, 그대로 쓴 문단 60%. KR3 공개 후 24시간 순방문자 30명, 의뢰 버튼 클릭률 5%. KR4 4주 뒤(12/22) 월 순방문자 50명, 실제 의뢰 1건.

## 4. 가설 및 지표
실제 방문자(불특정 다수)의 GA4 이벤트와 UTM으로 측정한다. 공개 후 24시간 기준, 표본 30명 미만이면 방향성만 판단한다.

| 사용자 가설 | 지표 (GA4 이벤트) | 목표 (공개 후 24시간) |
|---|---|---|
| H1 (U1) 과정을 보면 맡기고 싶어진다 | 상세 75% 스크롤 비율, 상세→의뢰 버튼 클릭률 | 40% 이상, 5% 이상 |
| H2 (U2) 한 줄이면 쉽게 의뢰한다 | 한 줄 입력→의뢰서 이동률, form_start→submit 시간 | 50% 이상, 제출 시 3분 이내 |

| 관리자 가설 | 지표 | 목표 |
|---|---|---|
| H3 (A2) 메모만으로 빨리 게시한다 | 메모 입력~게시 시간 | 건당 20분, 4건 80분 이내 |
| H4 (A2) 초안을 믿고 쓸 수 있다 | 없는 사실 / 그대로 쓴 문단 | 0건 / 60% 이상 |
| H5 (A3) 문구를 고르기만 하면 된다 | 복사 시간, 문구 A/B/C별 클릭(utm_content) | 1분 이내, 최고안이 최저안의 2배 |
| H6 (A1) 문구가 방문을 데려온다 | 채널별 순방문자(utm_source) | 24시간 30명 → 4주 50명·의뢰 1건 |

- **고객 정의**: 1순위는 포트폴리오로 디자이너를 고르는 소상공인과 스타트업 마케터.
- **마케팅 메시지**: 카피는 "결과물만이 아니라 문제를 푼 과정까지 보여드려요", 과장 없이 쓴다.

## 5. 기능적 요구사항
| 화면 | 기능 |
|---|---|
| 방문자 | F1 한 줄 의뢰, F2 의뢰서(희망 일정, 레퍼런스 작업과 링크, 사진 3장), F3 작업 목록과 상세(다른 프로젝트) |
| 관리자 | F4 작업 입력(정보, 이미지, 메모 3칸), F5 AI 초안(아티팩트 0원, 문장 틀, 보충할 점), F6 미리보기와 게시(직접 쓰기), F7 문구 3안(복사, 다른 문구) |

**유즈케이스**: 운영자는 메모, 초안 확인, 게시, 문구 복사 순서, 방문자는 인스타그램에서 와서 작업을 읽고 한 줄로 의뢰. **출시 이후**: 챗봇, 의뢰 AI 분석, 자동 게시.

## 6. 비기능적 요구사항
- **동시 접속과 성능**: 방문자 동시 50명, 작업 상세 2.5초, AI 초안 1분 이내
- **비용, 보안, 안정성**: AI는 운영자의 Claude 요금제로 비용 0원, 관리자 화면은 로그인, 메모는 관리자 전용. AI가 안 되면 문장 틀이나 직접 쓰기, 이름 · 이메일 · 링크는 제출 전 검사.

## 7. 디자인 요구사항
- **방향**: 디자인 시스템, '초안 · 검토 필요' 표시, 360px, 버튼 44px, 대비 4.5:1, 다크 모드. [프로토타입](../prototype.html), [시안](https://claude.ai/artifact/4WLPHZ2fxuUN4uYXBvdAvE)
- **방문자 화면**: 홈은 헤딩, 서비스, 한 줄 의뢰, 선택한 작업 순서. 작업 상세는 정보 줄, 01 요청, 02 과정, 03 결과, 다른 프로젝트, 의뢰 띠.
- **관리자 화면**: 왼쪽 메모 입력, 오른쪽 초안 편집과 미리보기, 게시 후 문구 화면.
