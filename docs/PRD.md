# PRD: AI 케이스 스터디 작성기 (Jae 블로그)

<sub>v1.5 (이전 버전은 커밋 기록) · 2026-11-25 J · [배포](https://blog---261117.web.app) · [프로토타입](../prototype.html) · [AI 작성기](https://claude.ai/artifact/P6pJ9oB2nfDGJKTfgviAzA) · [테스트 보고서](TEST_REPORT.md)</sub>

## 1. 개요
방문객이 거의 없고 작업 과정이 보이지 않아 의뢰가 들어오지 않는 1인 디자이너 블로그에서, 운영자가 메모만 넣으면 AI가 케이스 스터디와 인스타그램 문구를 만들어 소상공인과 스타트업 마케터를 데려오고, 한 줄 의뢰로 바로 의뢰하게 한다.

## 2. 문제
**데스크리서치**: 강점은 디자인과 구현을 함께 함, 약점은 빈 작업 섹션과 적은 방문자(SWOT). 고객은 과정을 보고 고르고, 외주 플랫폼은 포트폴리오로 신뢰를 준다(3C).

**문제 발굴과 검증** (공식 조사 원문 대조, 11/25)

| 문제 | 근거 (원문) | 판단 |
|---|---|---|
| A1 블로그에 방문객 · 일감이 적다 | 서울시 프리랜서 1,000명 실태조사(2018): 절반 이상이 정기적인 일감 없음 | 지지 |
| A2 작업을 케이스 스터디로 정리할 시간이 없다<br>A3 홍보 문구를 쓸 여유가 없다 | 한국디자인진흥원 「2024 디자인산업 인력실태조사」: 전문디자인업 6,392곳 중 84%가 4인 이하, 마케팅 · 영업 능력 '높음' 현재 27.4% < 요구 34.6%, 교육 필요 1위 대표자(27.1%) | 지지: 대표가 홍보까지 맡음 |
| U1 결과만 보고는 믿고 맡기기 어렵다 | 같은 조사: 프리랜서 디자이너 활용 업체 45.6%, 52.9%가 3개월 미만. Clutch(2026) 선택 기준: 창의성 39%, 전략적 사고 19%, 신뢰성 17%, 속도 · 가격 각 7% | 간접 지지: 처음 보는 디자이너의 생각과 신뢰를 봄 |
| U2 의뢰서 쓰기가 막막하다 | 직접 근거 없음 | 가설, GA4로 확인 |

**최종 정의**: 1인 디자이너 블로그는 방문객이 거의 없고, 찾아온 방문자도 문제를 푼 과정을 볼 수 없어 의뢰하지 않으며, 운영자는 작업을 정리하고 알릴 시간이 없다. 기존 방문자는 국내와 해외가 약 반반이다(운영자 GA4).

## 3. 해결 방안
| 문제 | 해결 방안 | 문제 | 해결 방안 |
|---|---|---|---|
| U1 | 요청 · 과정 · 결과를 보여 주고 의뢰 버튼 (F3) | A1 | 게시마다 인스타그램 문구로 데려옴 (F7) |
| U2 | 한 줄로 비슷한 작업, 미리 채운 의뢰서 (F1, F2) | A2, A3 | AI 초안 확인 후 게시, 문구 3안 복사 (F4~F7) |

- **솔루션 정의**: 운영자는 메모만 남기고, 방문자는 과정을 보고 한 줄로 의뢰한다.
- **AS-IS → TO-BE**: 컨셉 정리 안 된 작업 → AI 정리 후 사람이 확인. 타겟 적은 방문자 → 소셜에서 온 국내 · 해외 방문자. 비즈니스 모델 의뢰 수주(AI 비용 0원). 기능 빈 카드 · 긴 폼 → 작성기 · 상세 · 한 줄 의뢰 · 문구. 디자인 이미지 카드 → 과정을 읽는 상세.
- **예상 성과 (OKR)**: O 작업 4건을 한나절에 올리고 방문자가 과정을 보고 의뢰를 시작한다. KR1 4건, 건당 20분 이내(11/25). KR2 없는 사실 0건, 그대로 쓴 문단 60%. KR3 24시간 순방문자 30명, 클릭률 5%. KR4 12/22 월 순방문자 50명, 의뢰 1건.

## 4. 가설 및 지표
방문자 가설은 GA4 이벤트(D34)와 UTM으로 공개 후 24시간 측정, 표본 30명 미만이면 방향성만 본다.

| 가설 | 지표 | 목표 |
|---|---|---|
| H1 (U1) 과정을 보면 맡긴다 | case_view 대비 request_click | 5% 이상 |
| H2 (U2) 한 줄이면 쉽게 의뢰한다 | form_start 대비 form_submit, form_error | 50% 이상 |
| H3 (A2) 메모로 빨리 게시한다 | 메모 입력~게시 시간 (운영자 실측) | 건당 20분, 4건 80분 |
| H4 (A2) 초안을 믿고 쓸 수 있다 | 없는 사실 / 그대로 쓴 문단 (운영자 실측) | 0건 / 60% 이상 |
| H5 (A3) 문구는 고르기만 한다 | 복사 시간, 문구별 클릭(utm_content) | 1분 이내 |
| H6 (A1) 문구가 방문을 부른다 | 채널별 순방문자(utm_source) | 24시간 30명 |

**고객 정의**: 포트폴리오로 디자이너를 고르는 소상공인과 스타트업 마케터(국내 · 해외). **마케팅 메시지**: "결과물만이 아니라 문제를 푼 과정까지 보여드려요", 과장 없이.

## 5. 기능적 요구사항
- **방문자**: F1 한 줄 의뢰, F2 의뢰서(희망 일정, 레퍼런스 작업과 링크, 사진 3장), F3 작업 목록과 상세(다른 프로젝트), 고정 문구 한국어 ⇄ English(D33)
- **관리자**: F4 작업 입력(정보, 이미지와 타이틀 이미지 선택, 메모 3칸), F5 AI 초안(아티팩트 0원, 문장 틀, 보충할 점), F6 미리보기와 게시(직접 쓰기), F7 문구 3안(복사, 다른 문구)
- **유즈케이스**: 운영자는 메모 → 초안 확인 → 게시 → 문구 복사, 방문자는 소셜 링크 → 작업 읽기 → 한 줄 의뢰.

## 6. 비기능적 요구사항
동시 50명, 작업 상세 2.5초, AI 초안 1분 이내. AI는 운영자 Claude 요금제로 0원, 관리자는 로그인, 메모는 관리자 전용, AI가 안 되면 문장 틀, 이름 · 이메일 · 링크는 제출 전 검사.

## 7. 디자인 요구사항
디자인 시스템, '초안 · 검토 필요' 표시, 360px, 버튼 44px, 대비 4.5:1([프로토타입](../prototype.html), [시안](https://claude.ai/artifact/4WLPHZ2fxuUN4uYXBvdAvE)). 작업 상세는 정보 줄, 01 요청, 02 과정, 03 결과, 다른 프로젝트, 의뢰 띠. 관리자는 왼쪽 입력, 오른쪽 미리보기.
