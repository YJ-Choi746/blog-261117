# PRD: AI 케이스 스터디 작성기 (Jae 블로그)

## 1. 기본 정보, 2. 개요
버전 v0.8 (이전 버전은 커밋 기록), 2026년 11월 24일 J 작성. 배포 주소 https://blog---261117.web.app, 관련 문서 [테스트 보고서](TEST_REPORT.md), [의사결정 로그](DECISION_LOG.md), [성공 실패 로그](SUCCESS_FAILURE_LOG.md)

**개요**: 운영자가 작업 메모만 넣으면 AI가 케이스 스터디와 인스타그램 문구 초안을 만들고, 방문자는 작업 페이지에서 바로 의뢰한다.

## 3. 문제
**데스크리서치**: SWOT으로 보면 디자인과 구현을 모두 하는 것이 강점, 비어 있는 작업 섹션이 약점이다. 케이스 스터디는 검색과 SNS에 다시 쓸 수 있는 기회이고, 포트폴리오로 신뢰를 주는 외주 플랫폼이 위협이다. 3C로 보면 고객은 내 문제를 어떻게 풀지 보고 디자이너를 고르는데, 자사는 작업이 있어도 정리되지 않았다.

**문제 발굴**
- U1 방문자: 작업물과 작업 과정을 볼 수 없다.
- A1 운영자: 작업을 케이스 스터디로 정리할 시간이 없다.
- A2 운영자: 작업을 알릴 홍보 문구를 쓸 여유가 없다.
- U2 방문자: 디자이너에게 물어볼 곳이 없다.

**문제 검증**: 의뢰자가 작업 과정을 신뢰의 근거로 삼는지, 1인 프리랜서가 정리 시간이 부족한지 데스크 리서치로 확인한다. 출처는 공공기관 통계, 학술 논문, 공식 리포트만 원문으로 확인해 쓰고, 결과는 검증 후 적는다.

**최종 정의** (U1, A1, A2는 Must, U2는 Should): 방문자는 작업물과 작업 과정을 볼 수 없어 디자이너를 신뢰하지 못하고, 1인 운영자는 작업을 케이스 스터디로 정리할 시간이 없어 포트폴리오가 비어 있다.

## 4. 해결 방안
| 문제 | 해결 방안 |
|---|---|
| U1 방문자: 작업물과 작업 과정을 볼 수 없다 | 작업 상세에서 과정을 보여 주고 바로 의뢰하게 한다 (F4, F5) |
| A1 운영자: 작업을 케이스 스터디로 정리할 시간이 없다 | 메모만 쓰면 AI가 초안을 쓰고 운영자는 고쳐 게시한다 (F1, F2, F3, F7) |
| A2 운영자: 작업을 알릴 홍보 문구를 쓸 여유가 없다 | 인스타그램 문구를 만들어 복사만 하면 된다 (F6) |
| U2 방문자: 디자이너에게 물어볼 곳이 없다 | 사이트 내용만 근거로 답하는 챗봇 (F9, Should) |

- **4.1 솔루션 정의**: 운영자가 작업 메모만 남기면 AI가 케이스 스터디와 홍보 문구를 만들어 포트폴리오를 채우고, 방문자는 문제를 푼 과정까지 보고 같은 화면에서 의뢰한다.

**4.2 AS-IS / TO-BE**
| 구분 | AS-IS | TO-BE |
|---|---|---|
| 컨셉 | 작업은 있지만 사이트가 비어 있다 | AI가 정리하고 사람은 검토 후 게시 |
| 타겟 | 근거 없는 방문자, 바쁜 운영자 | 과정을 보고 믿는 방문자, 시간을 아낀 운영자 |
| 비즈니스 모델과 가격 | 의뢰 수주가 수익원 | 같음, 건당 AI 비용 100원 이하 목표 |
| 기능 | 빈 작업 카드 | 작성기, 작업 상세와 의뢰 버튼, 인스타그램 문구 |
| 디자인 | 이미지와 이름만 있는 카드 | 읽는 순서대로 한 열, 관리자는 입력과 초안 나란히 |

- **4.3 예상 성과 (OKR)**: 목표는 신뢰한 방문자의 의뢰 문의를 늘리는 것이다. KR1 11월 25일까지 케이스 스터디 4건 게시, KR2 정리 시간 50% 단축, KR3 출시 4주 뒤 의뢰 전환 20% 증가.

## 5. 가설 및 지표
| 가설 | 지표 | 목표 |
|---|---|---|
| 1 | (A1) AI 초안이 정리 시간을 줄인다 | 한 건 작성 시간 | 50% 단축 |
| 2 | (A1) AI 초안은 믿을 만하다 | 메모에 없는 사실 수 | 0건 |
| 3 | (U1) 케이스 스터디가 의뢰로 이어진다 | 작업 조회 후 의뢰 비율 | 20% 증가 |
| 4 | (A2) 인스타그램 문구가 홍보를 돕는다 | 문구를 복사한 작업 비율 | 80% |

- **5.2 고객 정의**: 1순위는 포트폴리오로 디자이너를 비교하는 소상공인과 스타트업 마케터다. AI 기능은 운영자가 쓴다.
- **5.3 마케팅 메시지**: "결과물만이 아니라 문제를 푼 과정까지 보여드려요." 성과는 과장하지 않고, 클라이언트 실명은 동의한 경우에만 쓴다.

## 6. 기능적 요구사항
| 기능 | 정의 | 우선순위 |
|---|---|---|
| F1 입력, F2 AI 생성, F3 게시 | 메모로 초안을 만들고 고쳐서 게시 | Must |
| F4 작업 상세, F5 의뢰 연결 | 실제 작업을 보여 주고 의뢰 폼으로 연결 | Must |
| F6 인스타그램 문구, F7 실패 대체 | 문구 생성과 복사, AI 실패 시 직접 작성 | Must |
| F8 GA4 이벤트, F9 챗봇 | 전환 측정, 방문자 질문 답변 | Should |

**유즈케이스**: 운영자는 작업을 입력하고 AI 초안을 고쳐 게시한 뒤 문구를 복사한다. 방문자는 작업 상세를 읽고 의뢰한다. SNS 자동 게시는 범위 밖이다.

## 7. 비기능적 요구사항
