## 2. 개요

의뢰 수주가 목적인 1인 디자이너 블로그에 작업물과 작업 과정이 비어 있어, 방문자가 작성자를 신뢰하지 못하고 의뢰하지 않는다. **운영자가 작업 이미지와 짧은 메모만 입력하면 AI가 케이스 스터디와 SNS 홍보 문구 초안을 만들어** 포트폴리오를 채우고, 작업 페이지에서 바로 의뢰로 연결한다.

## 3. 문제

### 3.1 데스크리서치

**3.1.1 SWOT**

| 강점 (S) | 약점 (W) |
|---|---|
| 디자인과 구현을 모두 함, 실제 작업 보유, 블로그·포트폴리오·의뢰 폼이 한 사이트 | 작업 섹션이 플레이스홀더, 작성자 소개·후기 없음, SNS 링크 미연결, 1인 운영으로 콘텐츠 정리 시간 부족 |
| **기회 (O)** | **위협 (T)** |
| 케이스 스터디는 검색 유입·SNS 공유 콘텐츠로 재사용 가능, AI로 정리 시간 단축 | 외주 플랫폼은 리뷰·포트폴리오가 기본 제공되어 신뢰 비교에서 불리 |

**3.1.2 3C**: (Customer) 의뢰자는 결과물뿐 아니라 "내 문제를 어떻게 풀어줄지"를 보고 디자이너를 고른다. (Competitor) 외주 플랫폼은 리뷰와 포트폴리오로 신뢰를 준다. (Company) 실제 작업은 있으나 정리되지 않아 신뢰 근거로 쓰이지 못한다.

### 3.2 문제 발굴

| # | 관점 | 문제 | 솔루션 방향 |
|---|---|---|---|
| U1 | 사용자 | 작업물과 과정을 볼 수 없어 실력을 판단하지 못한다 | 케이스 스터디 게시 |
| U2 | 사용자 | 작성자가 누구이고 어떻게 일하는지 물어볼 곳이 없다 | 사이트 근거 기반 질의응답 챗봇 |
| U3 | 사용자 | 내 업종에 맞는 디자이너인지 모르겠다 | 맞춤 작업 추천 |
| U4 | 사용자 | 의뢰서에 무엇을 적어야 할지 막막하다 | 제출 전 AI 누락 점검 |
| A1 | 관리자 | 작업이 끝나도 케이스 스터디로 정리할 시간이 없다 | AI 케이스 스터디 초안 |
| A2 | 관리자 | 작업을 알릴 SNS 문구를 따로 쓸 여유가 없다 | AI SNS 문구 생성 |

### 3.3 문제 검증

- **3.3.1 계획**: 11/24 오전, 디자인 외주 의뢰 경험자 2~3명·프리랜서 2명 5분 인터뷰. "디자이너를 고를 때 무엇을 보고 믿었나", "포트폴리오 정리를 미루는 이유"
- **3.3.2 결과 및 인사이트**: [인터뷰 후 기입]

### 3.4 문제 최종 정의

**3.4.1 우선순위 (MoSCoW)**: U1·A1·A2는 **Must**. 신뢰의 근거(콘텐츠)가 없으면 다른 해결책이 작동하지 않고, 결과물이 사이트에 남아 방문자 확보에도 쓰인다. U2는 **Should**. 케이스 스터디가 챗봇의 답변 근거가 되므로 Must 완료 후 착수. U3은 작업물이 충분히 쌓인 뒤, U4는 신뢰 문제 해결 후 다음 단계로 이월.

**3.4.2 최종 정의**
> 방문자는 작업물과 작업 과정을 볼 수 없어 디자이너를 신뢰하지 못해 의뢰하지 않고, 1인 운영자는 작업이 끝나도 이를 케이스 스터디로 정리할 시간이 없어 포트폴리오가 비어 있다.

## 4. 해결 방안

### 4.1 솔루션 정의

운영자의 작업 정리 → 게시 → SNS 확산을 AI가 한 흐름으로 자동화해, 방문자는 과정까지 보이는 작업으로 디자이너를 판단하고 같은 화면에서 의뢰한다.

### 4.2 AS-IS / TO-BE

| 구분 | AS-IS | TO-BE |
|---|---|---|
| 컨셉 | 작업은 있으나 정리되지 않아 사이트가 비어 있음 | 메모만 남기면 AI가 정리, 운영자는 검토·게시 |
| 타겟 | 방문자: 판단 근거 없음 / 운영자: 정리 시간 없음 | 방문자: 과정까지 보고 신뢰 / 운영자: 정리 시간 단축 |
| 비즈니스 모델 | 의뢰 수주가 수익원 | 동일. 운영비는 건당 LLM API 비용(측정 예정) |
| 기능 | 플레이스홀더 작업 카드 | 케이스 스터디 작성기, 작업 상세 + 의뢰 CTA, SNS 문구, (Should) 챗봇 |
| 디자인 | 이미지·이름 카드 | 커버 → 한 줄 요약 → 문제 → 과정 → 결과 → 의뢰 버튼 |

### 4.3 예상 성과 (OKR)

- **O**: 방문자가 작업을 보고 신뢰해 의뢰를 시작하게 한다.
- **KR1**: 출시 시점까지 케이스 스터디 4건 이상 게시, 플레이스홀더 0개
- **KR2**: 케이스 스터디 1건 정리 시간 수동 대비 50% 이상 단축
- **KR3**: 작업 상세 조회 → 의뢰 폼 시작 전환율, 출시 후 2주 기준선 측정 후 목표 확정

## 5. 가설 및 지표

### 5.1 핵심 지표

| 가설 | 지표 | 측정 | 목표 |
|---|---|---|---|
| H1. AI 초안이 정리 시간을 줄인다 | 건당 작성 시간 (수동 1건 vs AI) | 실제 작업으로 측정 | 50% 단축 |
| H2. AI 초안은 믿고 쓸 만하다 | 메모에 없는 사실 생성 건수 / 수정 없이 쓴 문단 비율 | 생성 결과 검토 | 0건 / 60% 이상 |
| H3. 케이스 스터디가 의뢰로 이어진다 | 작업 상세 → 의뢰 버튼 클릭 → 제출 | GA4 이벤트 | 기준선 측정 |
| H4. (Should) 챗봇이 질문 단계 이탈을 줄인다 | 근거 있는 답변 비율 / 챗봇 → 의뢰 전환 | 테스트 질문·GA4 | 90% 이상 / 기준선 |

GA4 이벤트: `case_view` · `case_cta_click` · `form_start` · `form_submit` · (Should) `chat_open`

### 5.2 고객 정의

- **1순위 고객 (의뢰자)**: 브랜드·상세페이지 디자인이 필요하고, 포트폴리오로 디자이너를 비교하는 소상공인·스타트업 마케터
- **AI 기능 사용자 (운영자)**: 작업과 콘텐츠 관리를 혼자 병행하는 1인 디자이너

### 5.3 마케팅 메시지

- 핵심 카피: "결과물만이 아니라 문제를 푼 과정까지 보여드려요"
- 가이드: 케이스 스터디는 성과를 과장하지 않고 메모에 있는 사실만 쓴다, 클라이언트 실명은 동의된 경우만
- 채널: 게시와 동시에 생성된 문구로 인스타그램·비핸스 공유, 사이트의 SNS 링크 연결

## 6. 기능적 요구사항

| ID | 기능 | 관점 | 설명 | 우선순위 |
|---|---|---|---|---|
| F1 | 작업 입력 폼 | 관리자 | 작업명·분야·업종·기간·이미지·메모(요청, 한 일, 결과) 입력 | Must |
| F2 | AI 케이스 스터디 생성 | 관리자 | 제목·한 줄 요약·문제/과정/결과 본문·태그를 JSON으로 생성 | Must |
| F3 | 편집·게시 | 관리자 | 초안 수정, 상태(초안/게시) 관리 | Must |
| F4 | 작업 목록·상세 페이지 | 사용자 | 홈 '선택한 작업' 플레이스홀더 교체, 케이스 스터디 상세 | Must |
| F5 | 의뢰 연결 | 사용자 | 상세 하단 "이런 작업 의뢰하기", 의뢰 폼에 분야 자동 선택 | Must |
| F6 | SNS 문구 생성 | 관리자 | 인스타그램·비핸스용 소개 문구와 해시태그, 복사 버튼 | Must |
| F7 | 실패 대체 경로 | 관리자 | AI 실패 시 빈 템플릿으로 직접 작성 가능 | Must |
| F8 | GA4 이벤트 | 공통 | 5.1 이벤트 | Should |
| F9 | 디자이너에게 물어보기 (챗봇) | 사용자·관리자 | 게시된 케이스 스터디·서비스 소개·프로세스만 근거로 답변, 근거 없으면 의뢰 폼 안내, 미답변 질문은 관리자에 기록 | Should (시간 남으면) |

**유즈케이스**: 운영자 작업 입력(F1) → AI 초안(F2) → 검토·게시(F3) → SNS 문구 복사·공유(F6) → 방문자 유입 → 작업 상세(F4) → 의뢰 버튼(F5) → 의뢰 폼 제출
**범위 밖**: SNS 자동 게시, 이미지 자동 생성·보정, 맞춤 작업 추천, 의뢰서 점검

## 7. 비기능적 요구사항

- 성능: AI 생성 20초 이내, 작업 상세 페이지 로드 2.5초 이내(이미지 압축)
- 보안: API 키는 서버 환경변수에만, 관리자 기능은 로그인 필수
- 신뢰성: 프롬프트에서 메모에 없는 수치·성과 생성 금지, 게시는 반드시 운영자 승인
- 챗봇(Should): 사이트 콘텐츠 밖의 답변 금지, 근거 없는 질문은 의뢰로 연결

## 8. 디자인 요구사항

- 기존 `docs/design-system.md` 톤·컴포넌트 유지
- 케이스 스터디 템플릿: 커버 이미지 → 한 줄 요약 → 문제 → 과정 → 결과 → 의뢰 버튼
- 관리자 화면: 입력(좌) / AI 초안 미리보기(우), 초안에 'AI 초안' 배지
