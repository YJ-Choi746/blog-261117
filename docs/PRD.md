# PRD: AI 케이스 스터디 작성기 (Jae 블로그)

<sub>1. 기본 정보: 버전 v0.9 (이전 버전은 커밋 기록), 2026년 11월 24일 J 작성, 배포 https://blog---261117.web.app</sub>

## 2. 개요
운영자가 작업 메모만 넣으면 AI가 케이스 스터디와 인스타그램 문구 초안을 만들고, 방문자는 작업 페이지에서 바로 의뢰한다.

## 3. 문제
**데스크리서치**: 강점은 디자인과 구현을 모두 한다는 점, 약점은 비어 있는 작업 섹션이다. 케이스 스터디는 검색과 SNS에 다시 쓸 수 있는 기회이고, 포트폴리오로 신뢰를 주는 외주 플랫폼이 위협이다(SWOT). 고객은 내 문제를 어떻게 풀지 보고 디자이너를 고르지만, 자사 작업은 정리되지 않았다(3C).

**문제 발굴**
- U1 방문자: 작업물과 작업 과정을 볼 수 없다.
- A1 운영자: 작업을 케이스 스터디로 정리할 시간이 없다.
- A2 운영자: 작업을 알릴 홍보 문구를 쓸 여유가 없다.
- U2 방문자: 디자이너에게 물어볼 곳이 없다.

**문제 검증**: 의뢰자가 작업 과정을 신뢰 근거로 삼는지, 1인 프리랜서가 정리 시간이 부족한지 데스크 리서치로 확인한다. 공공 통계, 학술 논문, 공식 리포트만 원문으로 확인해 쓴다. 결과: 검증 후 기입

**최종 정의** (U1, A1, A2는 Must, U2는 Should): 방문자는 작업물과 작업 과정을 볼 수 없어 디자이너를 신뢰하지 못하고, 1인 운영자는 작업을 케이스 스터디로 정리할 시간이 없어 포트폴리오가 비어 있다.

## 4. 해결 방안
| 문제 | 해결 방안 |
|---|---|
| U1 방문자: 작업물과 작업 과정을 볼 수 없다 | 작업 상세에서 과정을 보여 주고 의뢰로 잇는다 (F4, F5, F8) |
| A1 운영자: 작업을 케이스 스터디로 정리할 시간이 없다 | 메모로 AI가 초안을 쓰고 운영자가 게시한다 (F1~F3, F7) |
| A2 운영자: 작업을 알릴 홍보 문구를 쓸 여유가 없다 | 인스타그램 문구를 만들어 복사한다 (F6) |
| U2 방문자: 디자이너에게 물어볼 곳이 없다 | 사이트 내용으로 답하는 챗봇 (F9, Should) |

- **4.1 솔루션 정의**: 메모만 남기면 AI가 케이스 스터디와 홍보 문구를 만들고, 방문자는 과정을 보고 바로 의뢰한다.

**4.2 AS-IS / TO-BE**
| 구분 | AS-IS | TO-BE |
|---|---|---|
| 컨셉 | 작업이 정리되지 않음 | AI가 정리, 사람이 게시 |
| 타겟 | 근거 없는 방문자, 바쁜 운영자 | 믿는 방문자, 시간을 아낀 운영자 |
| 비즈니스 모델과 가격 | 의뢰 수주 | 같음, 건당 AI 비용 100원 이하 |
| 기능 | 빈 작업 카드 | 작성기, 작업 상세, 문구, 전환 측정 |
| 디자인 | 이미지와 이름 카드 | 과정을 읽는 상세 (8장 참고) |

- **4.3 예상 성과 (OKR)**: 목표는 의뢰 문의 증가. KR1 25일까지 케이스 스터디 4건, KR2 정리 시간 50% 단축, KR3 출시 4주 뒤 의뢰 전환 20% 증가.

## 5. 가설 및 지표
| 가설 | 지표 | 목표 |
|---|---|---|
| H1 (A1) 정리 시간이 준다 | 한 건 작성 시간 | 50% 단축 |
| H2 (A1) 초안을 믿을 수 있다 | 없는 사실 수, 고치지 않은 문단 | 0건, 60% |
| H3 (U1) 작업이 의뢰로 이어진다 | 작업 조회 후 의뢰 비율 (F8) | 20% 증가 |
| H4 (A2) 홍보가 쉬워진다 | 문구를 복사한 작업 비율 | 80% |

- **5.2 고객 정의**: 1순위는 포트폴리오로 디자이너를 비교하는 소상공인과 스타트업 마케터다.
- **5.3 마케팅 메시지**: "결과물만이 아니라 문제를 푼 과정까지 보여드려요." 과장 없이, 실명은 동의 시만.

## 6. 기능적 요구사항
| 기능 | 정의 | 우선순위 |
|---|---|---|
| F1 입력, F2 AI 생성, F3 게시 | 메모로 초안을 만들고 고쳐서 게시 | Must |
| F4 작업 상세, F5 의뢰 연결 | 실제 작업을 보여 주고 의뢰 폼으로 연결 | Must |
| F6 인스타그램 문구, F7 실패 대체 | 문구 생성과 복사, AI 실패 시 직접 작성 | Must |
| F8 GA4 이벤트, F9 챗봇 | 작업 조회와 의뢰를 기록해 H3를 잰다(Must), 챗봇(Should) | Must, Should |

**유즈케이스**: 운영자는 작업을 입력하고 초안을 고쳐 게시한 뒤 문구를 복사하고, 방문자는 작업 상세를 읽고 의뢰한다. 이전 버전의 의뢰 관리 기능은 유지한다.

## 7. 비기능적 요구사항
동시 접속 50명, AI 생성 20초, 상세 2.5초 안을 목표로 한다. API 키는 서버에만 두고, 관리자 기능은 로그인으로 막는다. 게시는 운영자가 승인하고, 메모와 비공개 실명은 관리자 전용으로 둔다.

## 8. 디자인 요구사항
디자인 시스템을 따르고, AI가 쓴 칸에 'AI 초안' 배지, 휴대폰 360px 대응. 참고: [디자인 시안](https://claude.ai/artifact/4WLPHZ2fxuUN4uYXBvdAvE), [디자인 시스템](https://claude.ai/artifact/9fFNM9rcdWzavxsyPd68KN), [프로토타입](../prototype.html)

- **사용자 화면**: 홈 '선택한 작업'(최신 3개), 작업 목록(분야 필터), 작업 상세(커버, 요약, 문제, 과정, 결과, 의뢰 버튼), 의뢰 폼(분야 자동 선택)
- **관리자 화면**: 작업 관리(초안, 게시), 작업 편집(왼쪽 입력, 오른쪽 AI 초안, 인스타그램 문구), 의뢰 관리(의뢰 카드, 상태)

## 9. 출시 및 운영 전략
- **개발 범위**: Must는 F1부터 F8까지(F1부터 F7은 24일 완료), F9는 그 뒤에만 한다.
- **출시 방식과 일정**: 25일 오전 AI 함수 배포, F8, 작업 4건 게시 후 15시 30분 최종 커밋.
- **테스트 방식과 일정**: 기능마다 단위 테스트, 25일 실제 작업으로 사실 오류와 시간 기록.
- **리스크와 해결**: 없는 수치는 숫자 경고와 검토로 막고, 함수가 늦으면 직접 작성(F7)한다.
