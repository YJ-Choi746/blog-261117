# PRD: AI 케이스 스터디 작성기 (Jae 블로그)

<sub>버전 v1.0 (이전 버전은 커밋 기록), 2026년 11월 24일 J 작성, 배포 https://blog---261117.web.app</sub>

## 1. 개요
- **문제**: 방문객이 거의 없고, 찾아온 방문자도 작업 과정을 볼 수 없어 의뢰하지 않는다.
- **타깃**: 포트폴리오로 디자이너를 고르는 소상공인과 스타트업 마케터, 1인 디자이너인 운영자.
- **해결**: 메모만 넣으면 AI가 케이스 스터디와 인스타그램 문구를 만들어, 방문자를 데려오고 바로 의뢰하게 한다.

## 2. 문제
**데스크리서치**: 디자인과 구현을 모두 하는 것이 강점, 비어 있는 작업 섹션과 적은 방문자가 약점이다(SWOT). 고객은 내 문제를 어떻게 풀지 보고 디자이너를 고르고, 외주 플랫폼은 포트폴리오로 신뢰를 준다(3C).

**문제 발굴**
- A3 운영자: 방문객이 거의 없어 의뢰할 사람이 적다.
- U1 방문자: 작업물과 과정을 볼 수 없다.
- A1 운영자: 케이스 스터디를 쓸 시간이 없다.
- A2 운영자: 홍보 문구를 쓸 여유가 없다.
- U2 방문자: 물어볼 곳이 없다.

**문제 검증**: 의뢰자가 작업 과정을 보고 믿는지, 1인 프리랜서가 정리와 홍보 시간이 부족한지 공공 통계, 학술 논문, 공식 리포트 원문으로 확인한다. 결과: 검증 후 기입

**최종 정의** (U2만 Should): 방문객이 거의 없고 찾아온 방문자도 작업 과정을 볼 수 없어 의뢰하지 않으며, 운영자는 작업을 정리하고 알릴 시간이 없다.

## 3. 해결 방안
| 문제 | 해결 방안 |
|---|---|
| A3 운영자: 방문객이 거의 없어 의뢰할 사람이 적다 | 케이스 스터디를 쌓고 인스타그램으로 데려온다 (F4, F6) |
| U1 방문자: 작업물과 과정을 볼 수 없다 | 과정을 보여 주고 의뢰로 잇는다 (F4, F5, F8) |
| A1 운영자: 케이스 스터디를 쓸 시간이 없다 | AI가 초안을 쓰고 운영자가 게시한다 (F1~F3, F7) |
| A2 운영자: 홍보 문구를 쓸 여유가 없다 | 인스타그램 문구를 만들어 복사한다 (F6) |

- **3.1 솔루션 정의**: AI가 메모로 케이스 스터디와 홍보 문구를 만들고, 방문자는 과정을 보고 의뢰한다.

| 3.2 구분 | AS-IS | TO-BE |
|---|---|---|
| 컨셉 | 작업이 정리되지 않음 | AI가 정리, 사람이 게시 |
| 타겟 | 적고 근거 없는 방문자, 바쁜 운영자 | 인스타그램으로 온 방문자, 시간을 아낀 운영자 |
| 비즈니스 모델과 가격 | 의뢰 수주 | 같음, 건당 AI 비용 100원 이하 |
| 기능 | 빈 작업 카드 | 작성기, 작업 상세, 문구, 전환 측정 |
| 디자인 | 이미지와 이름 카드 | 과정을 읽는 상세 (7장 참고) |

- **3.3 예상 성과 (OKR)**: 방문자를 모아 의뢰를 늘린다. KR1 케이스 스터디 4건(25일), KR2 정리 시간 50% 단축, KR3 4주 뒤 월 방문자 2배, 의뢰 전환 20% 증가.

## 4. 가설 및 지표
| 가설 | 지표 | 목표 |
|---|---|---|
| H1 (A1) 정리 시간이 준다 | 한 건 작성 시간 | 50% 단축 |
| H2 (A1) 초안을 믿을 수 있다 | 없는 사실, 고치지 않은 문단 | 0건, 60% |
| H3 (U1) 작업이 의뢰로 이어진다 | 작업 조회 후 의뢰 비율 (F8) | 20% 증가 |
| H4 (A2, A3) 홍보로 방문이 는다 | 문구 복사 비율, 월 방문자 | 80%, 2배 |

- **4.2 고객 정의**: 1순위는 소상공인과 스타트업 마케터(의뢰자)다.
- **4.3 마케팅 메시지**: "결과물만이 아니라 문제를 푼 과정까지 보여드려요." 과장 없이 쓴다.

## 5. 기능적 요구사항
- **Must**: F1 작업 입력, F2 AI 초안 생성, F3 편집과 게시, F4 작업 목록과 상세, F5 의뢰 연결, F6 인스타그램 문구, F7 AI 실패 시 직접 작성, F8 GA4 이벤트
- **Should**: F9 챗봇 (U2 해결, 사이트 내용으로만 답함)

**유즈케이스**: 운영자는 입력, AI 초안 수정, 게시, 문구 복사 순으로 쓰고, 방문자는 작업 상세를 읽고 의뢰한다. 이전 의뢰 관리 기능은 유지한다.

## 6. 비기능적 요구사항
- **동시 접속과 성능**: 방문자 동시 50명, 작업 상세 2.5초(이미지 900KB 이하), AI 초안 20초 안.
- **보안**: API 키는 서버에만 두고 관리자 화면은 로그인으로 막는다. 메모와 비공개 실명은 관리자 전용, 게시는 운영자 승인.
- **안정성과 측정**: AI나 저장이 실패해도 메모와 의뢰 메일은 남는다. 작업 조회, 의뢰, 문구 복사는 GA4로 기록한다.

## 7. 디자인 요구사항
- **방향**: 디자인 시스템, 'AI 초안' 배지, 360px, 버튼 44px, 대비 4.5:1, 다크 모드. [프로토타입](../prototype.html), [시안](https://claude.ai/artifact/4WLPHZ2fxuUN4uYXBvdAvE), [디자인 시스템](https://claude.ai/artifact/9fFNM9rcdWzavxsyPd68KN)
- **사용자 화면**: 홈은 한 줄 의뢰 입력과 선택한 작업, 작업 상세는 커버, 요약, 문제, 과정, 결과, 의뢰 버튼, 다른 프로젝트 순서.
- **관리자 화면**: 왼쪽 메모 입력, 오른쪽 AI 초안과 보충할 점, 직접 쓰기. 게시 뒤 인스타그램 문구 복사와 다른 문구 보기.

## 8. 출시 및 운영 전략
- **개발 범위**: Must는 F1부터 F8까지(F1부터 F7은 24일 완료), F9는 Must 뒤에만.
- **출시 방식과 일정**: 25일 오전 함수 배포, F8, 작업 4건 게시 후 15시 30분 최종 커밋.
- **테스트 방식과 일정**: 기능마다 단위 테스트, 25일 실제 작업으로 사실 오류와 시간 기록.
- **리스크와 해결**: 없는 수치는 숫자 경고와 검토로 막고, 함수가 늦으면 직접 작성(F7).
