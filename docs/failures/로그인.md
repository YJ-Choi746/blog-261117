# 실패 로그 — 로그인 · 글쓰기 (US-01)

"관리자는 로그인 후에 글을 직접 쓸 수 있다"를 만들면서 몰랐던 것과 알아낸 것을 순서대로 적어요.

## 2026-11-17

### 1. GitHub Pages만으로 로그인이 되나?
- **몰랐던 것**: 지금 사이트에서 바로 로그인을 만들 수 있는지.
- **알아낸 것**: 안 돼요. GitHub Pages는 파일을 보여주기만 해서, 비밀번호를 확인하거나 글을 저장할 곳이 없어요.
- **해결**: 바깥 서비스 Firebase(로그인 + Firestore 데이터베이스)를 쓰기로 했어요. GitHub Pages에서 그대로 동작하고 무료예요. → `docs/decisions.md`

### 2. Firebase 설정값(apiKey)을 저장소에 올려도 되나?
- **몰랐던 것**: `apiKey`라는 이름 때문에 비밀번호처럼 숨겨야 하는지.
- **알아낸 것**: 웹용 설정값은 원래 브라우저에 공개되는 값이에요. 숨길 수도 없어요.
- **해결**: `js/firebase-config.js`에 그대로 두고, 보안은 `firestore.rules`로 지켜요.

### 3. 로그인만 확인하면 안전한가?
- **몰랐던 것**: "로그인한 사람만 쓸 수 있게" 하면 충분한지.
- **알아낸 것**: 아니에요. 설정값이 공개라서 누구나 Firebase에 새 계정을 만들어 로그인할 수 있어요.
- **해결**: 보안 규칙에서 "로그인했는가"가 아니라 **"관리자 UID인가"**로 쓰기를 막았어요 (`ADMIN_UID`).

### 4. 임시저장 글이 남에게 보이지 않을까?
- **해결**: 규칙에서 `status == "published"`인 글만 누구나 읽게 했어요. 글 목록도 발행 글만 불러와요. 남이 임시저장 글 주소를 열면 "글을 찾을 수 없어요"가 나와요.

### 5. 글 목록을 날짜순으로 불러오다 "색인 필요" 오류가 날 수 있음
- **알아낸 것**: Firestore에서 "발행된 글만(where) + 날짜순(orderBy)"을 함께 쓰면 복합 색인을 따로 만들어야 해요.
- **해결**: 발행 글만 불러온 뒤 정렬은 브라우저에서 해요. 글이 수백 개가 되기 전까지는 충분해요.

### 6. 본문에 HTML을 쓰면?
- **알아낸 것**: 본문을 그대로 `innerHTML`로 넣으면 `<script>` 같은 코드가 실행될 수 있어요(XSS).
- **해결**: `js/render.js`가 `textContent`만 써서 본문을 그려요. HTML은 글자로 보여요. 대신 간단한 서식(##, -, >, ```)은 직접 지원해요.

### 7. 로그인 뒤 이동할 주소(`?next=`)를 악용할 수 있나?
- **알아낸 것**: `next`에 아무 주소나 넣을 수 있으면, 로그인 후 다른 사이트로 보내는 데 쓰일 수 있어요.
- **해결**: 허용 목록(`write.html`)에 있는 곳만 이동해요.

### 8. Claude 작업 환경에서 Firebase SDK가 안 받아짐
- **증상**: `www.gstatic.com`(Firebase SDK 주소) 접속이 막혀 있어요. 실제 Firebase 프로젝트도 아직 없어요.
- **해결**: 브라우저 테스트(Playwright)에서 SDK 주소를 **가짜 Firebase**로 바꿔치기해서, 로그인 → 임시저장 → 발행 → 목록 → 로그아웃 흐름을 확인했어요. 12개 완료 기준 모두 통과 (`docs/user-stories.md`).
- **남은 확인**: 실제 Firebase에서 보안 규칙이 뜻대로 막는지는 연결 후 한 번 더 확인해야 해요 (`docs/firebase-setup.md` 6번).

### 9. 로그인 확인 전 편집기가 잠깐 보이는 문제
- **해결**: 로그인 상태를 확인하는 동안 "확인하는 중…"만 보이고, 관리자임이 확인되면 편집기를 보여줘요.

## 2026-11-17 · Firebase 설정값을 넣은 뒤 상태 확인

### 10. 설정값은 들어갔는데 아직 로그인·저장이 안 됨
- **확인 방법**: Firebase 서버에 직접 물어봤어요 (없는 계정으로 로그인 시도, 글 목록 읽기 시도). 아무것도 바뀌지 않는 확인이에요.
- **결과 1**: 로그인 → `CONFIGURATION_NOT_FOUND`. **Authentication을 아직 "시작하기" 하지 않은 상태**라는 뜻이에요.
- **결과 2**: Firestore → `Cloud Firestore API has not been used in project … or it is disabled`. **Firestore 데이터베이스를 아직 만들지 않은 상태**예요.
- **해결**: `docs/firebase-setup.md`의 3번(Authentication 시작 · 이메일/비밀번호 켜기 · 관리자 계정), 4번(승인된 도메인), 5번(Firestore 만들기 · 규칙 게시)을 하면 돼요.

### 11. 콘솔이 알려준 SDK 버전(13.4.0)과 코드의 버전(10.12.2)이 다름
- **알아낸 것**: 콘솔은 늘 최신 버전을 보여줘요. 사용하는 기능(이메일 로그인, Firestore 읽기·쓰기)은 10.12.2에서도 같아요.
- **결정**: 테스트를 마친 10.12.2를 그대로 써요. 올릴 때는 `js/firebase.js` 한 곳에서만 바꾸고 다시 테스트해요.
- **참고**: 콘솔 코드의 `getAnalytics`(방문 통계)는 쓰지 않아요. `measurementId`는 설정값에만 남겨 뒀어요.
